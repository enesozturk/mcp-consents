# Contributing

Thanks for helping. There are three kinds of contributions, from most to least common.

## 1. Submit an MCP server

The gallery covers **remote** MCP servers that sign users in with **OAuth** (the MCP authorization
spec). Servers that need no sign-in, or that only take an API key, have no consent screen to show.

**Issue:** use the [Submit an MCP server](../../issues/new?template=submit-mcp.yml) form.

**Pull request:** add one object to the array in [`catalog/extra.json`](catalog/extra.json).

| Field | Required | Notes |
| --- | --- | --- |
| `id` | yes | lowercase letters, digits and dashes, e.g. `acme-crm` |
| `name` | yes | product name as the provider writes it |
| `mcp_url` | yes | the server URL an MCP client connects to (`https://`) |
| `homepage` | yes | the product's site (`https://`) |
| `description` | yes | one sentence about what the MCP server does, under 300 characters |
| `author`, `docs`, `one_liner` | no | provider name, MCP docs page, short tagline |

Then check it:

```bash
npm install
npm run check-submissions -- --probe
```

The probe asks the server for its OAuth metadata only. It does not register a client, open a browser
or sign in. CI runs the same check on every pull request.

Please **do not** add screenshots, notes or scores. The maintainer records every consent screen with the
same test client and test account, so captures are comparable and no one's personal data is
committed. After merging, the new server shows up on the site once it has been recorded.

## 2. Corrections

A wrong description, an outdated screen, a score you disagree with: open an issue and link the
server page. Scores are opinionated on purpose (see the criteria in the [README](README.md#how-consent-screens-are-scored)),
but factual mistakes ("it does show the redirect URL") are always fixed.

If you represent a provider and redesigned your consent screen, say so in the issue and it will be
re-recorded.

## 3. Code

Fixes and improvements to the site, the API or the scanner are welcome. For anything larger than a
small fix, open an issue first so we can agree on the approach.

```bash
npm run dev          # http://localhost:3000
npm run typecheck
npm run build
```

- Keep the site light and minimal. The design is deliberate.
- Do not edit `src/data/gateways.json` or the images under `public/` by hand. They are generated by
  `scripts/prepare.cjs` from the maintainer's private recordings.
- The API and `llms.txt` are used by agents: keep their fields and query parameters backward compatible.

## Review

Every pull request is reviewed and merged by the maintainer. Small, focused pull requests get merged
fastest.
